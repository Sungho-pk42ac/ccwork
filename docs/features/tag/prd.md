# 태그 기능 PRD

## 1. 개요

노트에 태그를 추가·삭제·표시하는 기능을 구현한다. 사용자는 NoteEditor에서 태그를 입력하고, NoteList에서 태그를 확인할 수 있다. 태그는 노트 저장 시 함께 저장되며 별도 즉시 저장하지 않는다.

### 목표

- 노트에 자유 형식의 태그를 부여하여 분류할 수 있게 한다
- 기존 저장 플로우를 유지하면서 최소한의 변경으로 통합한다

### 성공 지표

- 태그 CRUD가 기존 노트 저장 플로우 안에서 정상 동작한다
- 기존 노트(tags 필드 없음)에서 오류 없이 폴백 처리된다

## 2. 사용자 스토리

| #    | 스토리                                        | 인수 조건                                                             |
| ---- | --------------------------------------------- | --------------------------------------------------------------------- |
| US-1 | 사용자는 노트 편집 시 태그를 추가할 수 있다   | 텍스트 입력 후 Enter 또는 쉼표(`,`)로 태그가 칩으로 추가된다          |
| US-2 | 사용자는 추가된 태그를 개별 삭제할 수 있다    | 칩의 X 버튼 클릭 시 해당 태그가 제거된다                              |
| US-3 | 사용자는 노트 목록에서 태그를 확인할 수 있다  | NoteItem에 태그 칩이 읽기 전용으로 표시된다 (태그 없으면 영역 미표시) |
| US-4 | 사용자는 중복 태그를 입력해도 하나만 유지된다 | `React`와 `react`는 동일 태그로 처리되며 소문자로 정규화 저장된다     |
| US-5 | 사용자는 빈 태그를 입력할 수 없다             | 빈 문자열·공백만 입력 시 태그가 추가되지 않는다                       |
| US-6 | 기존 노트를 열어도 오류가 발생하지 않는다     | tags 필드가 없는 노트는 빈 배열로 폴백된다                            |

## 4. Out of Scope

| 항목                   | 이유                                                            |
| ---------------------- | --------------------------------------------------------------- |
| 태그별 필터링/검색     | 1차 범위는 CRUD만. 필터링은 태그 데이터 안정화 후 별도 기능으로 |
| 태그 자동완성          | 기존 태그 목록 조회 API가 필요하며 별도 설계 필요               |
| 태그 색상/카테고리     | 현재 태그는 단순 문자열. 메타데이터 확장은 향후 고려            |
| 태그 개수/글자 수 제한 | spec에서 제한 없음으로 확정. 필요 시 향후 추가                  |

## 5. 용어 정의

| 용어                   | 정의                                                                           |
| ---------------------- | ------------------------------------------------------------------------------ |
| 태그 (Tag)             | 노트에 부여하는 자유 형식 문자열 라벨. 소문자로 정규화 저장된다                |
| 칩 (Chip)              | 태그를 시각적으로 표현하는 UI 요소. badge 형태로 나열되며 삭제 버튼을 포함한다 |
| 정규화 (Normalization) | 입력된 태그를 trim 후 소문자로 변환하는 처리. 중복 판별의 기준이 된다          |
| 폴백 (Fallback)        | tags 필드가 없는 기존 노트를 `tags ?? []`로 빈 배열 처리하는 하위 호환 전략    |
