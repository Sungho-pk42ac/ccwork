# Security Review 스킬

Refactor 완료 후 커밋 전, **타입 오류와 보안 취약점**을 점검하고 결과를 분류한다.
코드가 타입 안전하고 알려진 보안 문제가 없는 상태에서만 커밋하기 위한 게이트다.

## 입력

`$ARGUMENTS` = issues.md 내부 이슈 번호 (예: `1`)

## 왜 커밋 전 점검인가

Green에서 동작하게 만들고, Refactor에서 깔끔하게 다듬었더라도
TypeScript 컴파일러가 잡는 타입 오류나 의존성 취약점은 별도로 확인해야 한다.
테스트가 통과해도 `tsc --noEmit`은 실패할 수 있고, `npm audit`은 런타임과 무관한 공급망 문제를 찾아낸다.

---

## 실행 순서

### Step 1. 타입 검사

```bash
npx tsc --noEmit
```

출력에서 오류를 수집한다. 오류가 없으면 "타입 검사 통과"로 기록하고 Step 2로 넘어간다.

오류가 있으면 각 항목을 기록한다:

- 파일 경로 + 라인 번호
- 오류 코드 (TS2345 등)
- 오류 메시지

### Step 2. 의존성 취약점 검사

```bash
npm audit
```

출력에서 취약점을 수집한다. 취약점이 없으면 "의존성 검사 통과"로 기록하고 Step 3으로 넘어간다.

취약점이 있으면 각 항목을 기록한다:

- 패키지명 + 버전
- 심각도 (critical / high / moderate / low)
- 설명

### Step 3. 환경 변수 노출 검사

`.env` 파일에 정의된 변수가 `src/` 코드에서 직접 하드코딩되어 있는지 확인한다.

```bash
grep -r "API_KEY\|SECRET\|PASSWORD\|TOKEN\|PRIVATE" src/ --include="*.ts" --include="*.tsx"
```

`.env` 파일이 존재하면 그 안의 변수명도 `src/`에서 검색한다.
`process.env.XXX` 또는 `import.meta.env.XXX` 형태의 정상 참조는 제외한다.

### Step 4. 결과 분류 및 보고

수집된 모든 결과를 세 가지로 분류하여 개발자에게 보고한다.

```
## Security Review — Issue #{N}

### 즉시 수정 필요 (Critical)
빌드 실패를 유발하는 타입 오류, critical/high 취약점, 하드코딩된 시크릿

| # | 종류 | 내용 | 위치 |
|---|------|------|------|
| 1 | 타입 오류 | TS2345: ... | src/xxx.ts:10 |

### 권장 수정 (Warning)
moderate 취약점, 잠재적 타입 문제, 불필요한 any 사용

| # | 종류 | 내용 | 위치 |
|---|------|------|------|
| 1 | 취약점 | moderate: ... | package-name |

### 무시 가능 (Info)
low 취약점, devDependency 전용, 의도된 패턴

| # | 종류 | 내용 | 이유 |
|---|------|------|------|
| 1 | 취약점 | low: ... | devDependency 전용 |
```

AskUserQuestion으로 "즉시 수정 항목 처리 / 전체 승인 / 중단" 중 선택을 받는다.

### Step 5. 즉시 수정 처리

개발자가 승인한 "즉시 수정 필요" 항목만 처리한다.

- **타입 오류**: 해당 파일의 타입을 수정한다
- **취약점**: `npm audit fix` (--force 없이)로 안전하게 수정 가능한 것만 처리
- **시크릿 노출**: 하드코딩된 값을 환경 변수 참조로 변경

수정 후 `npm test`를 실행하여 회귀가 없는지 확인한다.

### Step 6. 재스캔

수정 후 Step 1~3을 다시 실행하여 클린 상태를 확인한다.

```
## 재스캔 결과

- 타입 검사: PASS / FAIL
- npm audit: N개 취약점 (critical: 0, high: 0)
- 환경 변수: 노출 없음

→ 커밋 가능 / 추가 수정 필요
```

모두 통과하면 "커밋 가능" 상태를 보고한다.

---

## 절대 금지

- **개발자 승인 없이 코드를 수정하는 것** — 판단이 필요한 항목은 반드시 승인 후 처리
- **테스트 파일을 수정하는 것**
- **`npm audit fix --force` 사용** — 메이저 버전 변경으로 호환성이 깨질 수 있다
- **분류 없이 결과를 나열하는 것** — 반드시 즉시/권장/무시로 분류
